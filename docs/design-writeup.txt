<b>Problem and scope.</b> VulnBrief v0.2 investigates up to three CVEs using live public sources and optional JSON/CSV inventory. It connects evidence to asset-version assessments and conditional follow-up drafts. The example inventory is fictional. Asset/CVE associations and supplied versions are user assertions, not scanner findings; configuration applicability remains unverified.

<b>Design decisions.</b> One LLM agent uses LangGraph for planning, native tool selection, observations and structured reporting. Six tools cover context, CVE records, CISA KEV, FIRST EPSS, supported vendor advisories and asset versions. The vendor adapter reads Palo Alto's live product-status table. Version arithmetic supports explicit numeric/hotfix branches; unsupported or conflicting inputs remain unverified. Python validates contracts and exact cited source fields; priorities and recommended actions come from the model. Failed requests use ERR identifiers separately from successful E evidence. Source CVSS metrics are attached directly and distinguished from model judgment.

<b>Workbench and persistence.</b> A local FastAPI/HTML interface accepts goals and inventories, exposes events and original evidence, and exports reports and task drafts. One queued worker limits API pressure. SQLite retains run snapshots and analyst draft-review states. Comparisons distinguish changed values from missing observations. Accepting a draft records review only; no system change or external ticket is executed. Uploaded inputs, database state and credentials are excluded from the source ZIP.

<b>Verification and limitations.</b> Tests cover source failures, missing values, field citations, error IDs, version boundaries, CSV validation, API queueing, persistent reviews and comparisons. Live data checks distinguish potentially affected, version-unaffected and unknown assets. A disclosed injected-timeout trace demonstrates model-selected recovery. The evaluation inventory retains quota/schema failures and labels baseline versus upgraded runs. Computer Use blocked browser visual verification because it could not establish the active URL confidently; API and static frontend checks were completed. These checks do not establish production reliability or detector precision/recall.

<b>Grounding and next steps.</b> Fresh source context and a separate LLM review can request one report repair, but model review can miss errors or create false positives. Missing EPSS is unknown, KEV absence does not prove safety, and historical guidance does not establish current patch availability. Quotas and incomplete records can terminate runs. Add more vendor adapters, configuration applicability checks, independent claim verification, graph checkpoints and access controls before wider deployment. The implementation used AI coding assistance; no public agent implementation was copied. The applicant should review and explain the code before submission.
