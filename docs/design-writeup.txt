<b>Problem and scope.</b> VulnBrief v0.3 investigates up to three CVEs using live public sources and optional JSON/CSV inventory. It connects evidence to asset-version assessments and conditional follow-up drafts. The example inventory is fictional. Asset/CVE associations and supplied versions are user assertions, not scanner findings; configuration applicability remains unverified.

<b>Design decisions.</b> One LLM agent uses LangGraph for planning, native tool selection, observations and structured reporting. Six tools cover context, CVE records, CISA KEV, FIRST EPSS, supported vendor advisories and asset versions. The vendor adapter reads Palo Alto's live product-status table. Version arithmetic supports explicit numeric/hotfix branches; unsupported or conflicting inputs remain unverified. Python validates contracts and exact cited source fields; priorities and recommended actions come from the model. Failed requests use ERR identifiers separately from successful E evidence. Source CVSS metrics are attached directly and distinguished from model judgment.

<b>Workbench and persistence.</b> A local FastAPI/HTML interface accepts goals and inventories, exposes events and exports reports and task drafts. A guided walkthrough labels recorded real runs separately from new live requests. A citation inspector shows the selected claim beside its exact source value and dates. One queued worker limits API pressure. SQLite retains snapshots and analyst review states. Comparisons distinguish changed values from missing observations. Draft acceptance records review only; no system change or external ticket is executed. Private inputs, database state and credentials are excluded from the source ZIP.

<b>Verification and limitations.</b> Unit/API and presentation tests cover source failures, missing values, citations, version boundaries, queueing and persistence. Isolated Chromium tests exercise reviewer navigation, modal focus, responsive layouts and automated accessibility checks at desktop, tablet and phone widths; actual screenshots were inspected. A genuine silent walkthrough is included. A repeatable, token-bounded evaluation harness records live trials, behavioral checks and unsuccessful outcomes; only executed cases count. Existing traces demonstrate model-selected recovery and unknown-data preservation. These checks do not establish full accessibility, semantic accuracy, production reliability or classifier precision/recall.

<b>Grounding and next steps.</b> Fresh source context and a separate LLM review can request one report repair, but model review can miss errors or create false positives. Missing EPSS is unknown, KEV absence does not prove safety, and historical guidance does not establish current patch availability. Quotas and incomplete records can terminate runs. Add more vendor adapters, configuration applicability checks, independent claim verification, graph checkpoints and access controls before wider deployment. The implementation used AI coding assistance; no public agent implementation was copied. The applicant should review and explain the code before submission.
